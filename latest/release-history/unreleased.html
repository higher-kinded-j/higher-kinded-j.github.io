Higher-Kinded-J: Composable Effects and Advanced Optics for Java

Unreleased: 0.6.0

Not released yet: these changes are on main, and the latest book describes them.

To try them, depend on 0.6.0-SNAPSHOT from the snapshots repository, as Gradle SNAPSHOT Configuration shows.

At a glance

  • javac checks what each step of a Path chain returns. A step of another kind of Path, or one that fails with an error the chain does not carry, is a compile error in the IDE as well as the build.
  • @ImportOptics pairs a JavaBeans-spelt wither with its getter: a witheMail beside geteMail() gives an eMail() lens.
  • A @GenerateFocus message that offers a navigator asks first for the renames it needs. Following its fix line no longer leads into another note or error.
  • A @GenerateMapping bean refusal's fix line compiles once followed, and names the near miss it passed over, such as setx(int) beside Integer getX().

Mapping

  • A bean property's fix line compiles once followed (#1149). The setter offered for eMails is seteMails, not setEMails. A rename to a keyword such as default is offered no marker, and a marker replaces the spec's own rename. A near miss such as setx(int) beside Integer getX() is named. See When an unpaired accessor is refused.
  • Two more PATCH-bean fix lines compile once followed (#1293). A legacy setter such as setTimeout(Integer) beside a rename of timeout is offered no @Unmapped marker, since the rename takes that name. A primitive word such as setx(int) is offered its wrapper, setX(Integer). See A method that only starts like an accessor.

Optics

  • @ImportOptics pairs a JavaBeans-spelt wither with its getter (#1148). A witheMail(String) beside geteMail(), as Lombok's beanspec capitalisation writes them, gives an eMail() lens, as withEMail beside getEMail() does. The processor says why it refuses a class whose only wither is with2D(int). See Wither Classes to Lenses.
  • A spec lens reads a getter inherited from two interfaces as javac does (#1136). An abstract source that inherits String name() from one interface and CharSequence name() from another is now read as returning String, so a Lens<Src, String> over it builds. A @ViaBuilder chain reads an inherited toBuilder() or build() the same way. See Compiler Messages.
  • Messages that offer a navigator ask first for the renames it needs (#1272). The note to widen items beside an Items with a navigator, and five other messages, now ask for one of the two to be renamed first. They also name a field such as last that the navigator could not reach. See Two fields with one navigator name.
  • OpticOpFunctor.map applies its function (#1154). It returned the instruction unchanged, so code that mapped a lifted OpticOp failed later with ClassCastException. Each OpticOp record now carries a continuation k, as an @EffectAlgebra operation does, and an interpreter hands each result to op.k() in place of wrapping it in Free.pure. See What an interpreter actually is.

Effect Paths

  • javac checks each chain step's kind of Path and error type (#1314). A step passed to via or another chaining method must be the chain's own kind of Path, so a mismatch is a compile error rather than an exception at run time. A step may still fail with a variant of the chain's error. See The Family Parameter.
  • EitherPath gains ensure (#1338): ensure(test, onFail) keeps a success whose value passes test and turns any other success into a failure built from its value, so a guard no longer needs an if returning a Left. See EitherPath.
  • TrampolinePath and FreePath combine three paths with zipWith3 (#1302): both already combined two paths with zipWith. The three-way combine stays lazy until run() or foldMap, so a deep chain stays stack-safe. See Combinable (Applicative).
  • NonDetPath gains six list operations that ListPath already had (#1337): lastOption, anyMatch, allMatch, takeWhile, dropWhile and get. Each behaves as its ListPath counterpart.
  • NonDetPath gains foldRight, fold and foldMap (#1322): with foldLeft, it now has the four folds that ListPath and StreamPath offer, and each behaves as its ListPath counterpart. See the Effect Path Cheatsheet.
  • Monoid.of builds a monoid from its empty value and its operation, and Monoids.bigDecimalAddition() sums money exactly (#1356). Monoid.of(Duration.ZERO, Duration::plus) takes the place of an anonymous class, and an existing Semigroup can be the operation. See Semigroup and Monoid.
  • A Selective of your own runs only the branch its condition picks (#1358). The default whenS ran its effect for a false condition, and the default ifS ran both branches. Both now leave the choice to select: one that keeps its contract skips what the condition does not pick, and one built from ap still runs every effect. See Selective.
  • mapError on MaybePath, TryPath and CompletableFuturePath carries the mapped error (#1332): recover after it sees that error, where it used to see the old one. A success is a Right and the mapper is not called. MaybePath and TryPath return an EitherPath. CompletableFuturePath returns a VResultPath. See Recoverable (MonadError).

Build and tooling

  • The HKJ checker names the fix beside javac's error for a mismatched step (#1314). error-type-mismatch says where to type the chain, as in write .<OrderError>mapError(...), or that the step's error needs mapping. path-type-mismatch now reads method-reference steps, VResultPath and the accumulating methods. See Compile-Time Checks.
  • A build with an HKJ plugin applied can set the checker's options (#1336). A hand-written -Xplugin:HKJChecker severity=warn failed the build with plug-in not found: HKJChecker. The Gradle and Maven plugins now add no checker argument when the build already names the checker. See Configuring the checker.
  • A build with the HKJ Gradle plugin can turn on Gradle's configuration cache (#1374). With the cache on, hkjInstallSkills and hkjDiagnostics failed, and so did every build with skills = true, which runs hkjInstallSkills. Both tasks now run with it, and the next build reuses the cache. See With the Plugin.
  • An OpenRewrite recipe adds the Path family to capability types (#1314). org.higherkindedj.openrewrite.AddPathFamily rewrites Chainable<A> to Chainable<?, A>, and likewise the other capability types, a PathProvider's createPath included. See 0.6.0 Path family.

Documentation

  • StreamPath docs no longer call it lazy where the source is read at once (#1290). The cheat sheet and home page describe sequences you can run more than once, and toStreamPath says the non-null focuses are collected into a list when it is called.
  • The StreamPath docs say when the source is read (#1278). Path.stream reads its whole stream when it is called, so the stream must be finite. Path.streamIterate, StreamPath.generate and StreamPath.fromSupplier build a fresh stream each time the path runs, so take can limit an infinite one. See Choosing the Right Streaming Tool.
  • The Effect Paths glossary gains three entries (#1301): FreeApPath, FreePath and GenericPath. Each gives a definition, its factories on Path, and its main operations. See Effect Paths.
  • The Effect Paths glossary gains four more entries (#1258): ReaderPath, TrampolinePath, WithStatePath and WriterPath. Each gives a definition, its factories on Path, its main operations and a link to its chapter page. See Effect Paths.
  • Five examples keep one kind of Path and one error type through their chains. Composition Patterns ran an IOPath step in an EitherPath chain, which throws when it runs; it now builds an IOPath chain. The Quickstart, a migration recipe and the hkj-guide and hkj-spring skills now name the chain's error type with a witness. See Composition Patterns.
  • Generated Javadoc uses an article only before a type the processor chose (#1307). A record, class, property or operation is named with none, as in field of {@link Address} and Lifts the {@code Charge} operation. A path or optic type keeps the article its name takes, as in Creates an {@link AffinePath}.
  • The hkj-guide skill turns guard clauses into ensure (#1338). A new migration recipe replaces a run of if (!ok) return Either.left(...) checks with one ensure step for each, and the skill's Error Handling table lists ensure.
  • The Profunctor javadoc states its composition law correctly (#1362). Two of its functions were swapped, so the law as written fails. It no longer says profunctors model the optics, which are van Laarhoven optics, and Bifunctor's javadoc names Function as the only Profunctor instance. See Profunctor.

Upgrading from 0.5.0

Before you upgrade

What a running program can notice

Core types

  • Validated.map, and map2 to map5 on its monad, throw NullPointerException when their function returns null (#1318). They threw KindUnwrapException, so catching that, or IllegalArgumentException, around the call no longer catches it. See Values, never null.
  • FunctionKindHelper.narrow throws KindUnwrapException, as the other kind helpers do (#1318). A null Kind threw NullPointerException, so catching that no longer catches it. Another type's Kind threw IllegalArgumentException, which KindUnwrapException extends, so catching that still does. See When narrow throws.
  • A Selective of your own no longer runs the effects its condition skips (#1358), unless its select is built from ap. The default whenS ran its effect on a false condition, and the default ifS ran both branches, so a failing effect's error could hide the condition's. Run any effect you relied on yourself. The library's own instances are unchanged.

Optics

  • Of two withers for one getter, @ImportOptics sets through the capitalised spelling (#1148): the lens for a class with both withEMail and witheMail beside eMail() set through whichever the class declared first. It now sets through withEMail, and a note names witheMail, which a spec interface's @Wither can choose.
  • An optic interpreter that wraps each result in Free.pure skips the operation's continuation (#1154): a program from OpticPrograms runs as before, but a function mapped onto an OpticOp, through OpticOpFunctor or Free.translate, is not applied. Hand the result to op.k() and return what it gives.

Effect Paths

  • A ValidationPath keeps its own semigroup through a step (#1314): the result of via, then, recoverWith and orElse accumulated with the step's semigroup, and now accumulates with the receiver's. After mapError, whose placeholder semigroup throws, a later accumulation now throws even past a step that had a semigroup; use mapErrorWith instead.
  • An EitherOrBothPath keeps its own semigroup through a recovery (#1314): the result of recoverWith and orElse accumulated with the recovery's semigroup, and now accumulates with the receiver's, as via and then already did.
  • mapError on MaybePath, TryPath and CompletableFuturePath applies the mapper (#1332): it used to hand back the same path, and it never called the mapper. A failure now runs the mapper, and recover sees that error. MaybePath and TryPath return an EitherPath. CompletableFuturePath returns a VResultPath. mapException still stays a TryPath.
