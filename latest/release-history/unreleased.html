Higher-Kinded-J: Composable Effects and Advanced Optics for Java

Unreleased: 0.5.0

Not released yet: these changes are on main, and the latest book describes them.

To try them, depend on 0.5.0-SNAPSHOT from the snapshots repository, as Gradle SNAPSHOT Configuration shows.

At a glance

  • Optics over a nullable field pass a nullness checker: every optic and Focus path type takes a @Nullable focus, as does each bridge into an Effect Path that says what a null focus becomes.
  • @PathSource has a page of its own, beside GenericPath in the Effect Path chapter.
  • StateT is built from its state function alone, and mapT takes only the transformation, as on every other transformer.

Mapping

Optics

  • Any two of Iso, Lens, Prism, Affine and Traversal compose directly with andThen (#1021). An Iso followed by a Traversal now returns a Traversal, and so does a Traversal followed by an Affine or an Iso, with no asTraversal() first. The composition table is read from the overloads, so it always matches the library. See Composition Rules Table.
  • A map written through an optic keeps its source's order (#1022): every optic that writes a Map, from Traversals.forMapValues to AtInstances.mapAt and Setter.forMapValues, hands back a map in the source's iteration order. An updated key keeps its place and a new key goes at the end. See Persistent and Third-Party Maps.
  • modifyWhen and branch on a Traversal call only the function their predicate picks (#1026). Each element is now tested first, so a function may assume the condition that guards it, and an expensive one runs only where it is needed. Lens.modifyWhen, modifyBranch and setIf test first too. See Complete, Runnable Example.
  • @ViaConstructor holds its order to the constructor (#906). An order that passes a value where the constructor's parameter names say another belongs, or that no constructor takes, is now refused at the spec method. Leave parameterOrder out and it is read from those names. See @ViaConstructor: constructor-only value types.
  • Optics over a nullable field pass a nullness checker (#767, #1017): every optic and Focus path type, and Kind, takes a nullable type, so the lens generated for a @Nullable component checks under JSpecify. A bridge into an effect type can say what a null focus becomes, as toEitherPath(source, error) does. See A focus that may be null.
  • nullable() keeps the focus type (#1017): FocusPath.nullable() and AffinePath.nullable() return the focus type without its null, so a chained focus(path.nullable(), error) or a var infers it where it inferred Object. A call written path.<String>nullable() still compiles. See .nullable(): Handle Null Values.
  • A Maybe component's Focus path reads and writes its Just value (#757): @GenerateFocus now widens a Maybe field through .some(Affines.just()). It used the Optional-only .some(), so the first read or write of the path threw ClassCastException. A Maybe nested in another container, such as List<Maybe<A>>, threw the same way. See Supported Container Types.
  • Setter.forList and Setter.forMapValues give the same result on every run (#1018): each time the effect from modifyF runs, it builds its own list or map. So an IO gives an equal value on every run, and the List applicative gives every combination of choices. Traversals.traverseMapValues does the same for an empty map. See Sequencing Effects in Collections.
  • A read through a traversal no longer rebuilds what it reads (#1056). Traversals.getAll, a TraversalPath's reads, IndexedTraversals.toIndexedList, getAll and length, asIndexedFold() and IxedInstances.get read each focus as asFold() does. So reading a list or map through an optic no longer builds a new one. See What reads cost.
  • A fold's query stops at its answer (#1056). preview, find, exists, all and isEmpty on Fold and TraversalPath, and IndexedFold's queries, visit no focus after the one that settles them. So exists over a long list returns at its first match. A path from traced still reads every focus, so its observer sees them all. See What reads cost.
  • A prism or affine that matches builds nothing it throws away (#1056). Prism.modifyF, Affine.modifyF, Traversal.andThen(Prism), Prism.andThen(Traversal) and Affine.andThen(Traversal) wrap the source with of only on a miss, and OptionalTraverse.traverse only for an empty Optional. See Prisms and affines on a miss.
  • A method named after a Java keyword takes a trailing underscore (#1056). An enum constant such as NEW or TRUE, a sealed subtype named Default, an @EffectAlgebra permit named Throw, or an imported withDefault crashed the processor. Their methods are now new_(), true_(), default_() and throw_(), and so are @GenerateErrorEnvelope factories. See Prisms.
  • .each() on a List path takes time in proportion to the list (#1063). A Focus path's .each(), which every generated List path uses, now rebuilds the list once instead of copying it at every element. On 100,000 elements that took several seconds, and now takes about a millisecond. EachInstances.arrayEach() rebuilds an array the same way. See Traversal allocation.

Effect Paths

  • StateT is built from its state function alone (#445): its constructor, create and StateTKindHelper.stateT take no Monad, and mapT takes only the transformation, as on every other transformer. The record holds only that function, so equals, hashCode and toString leave the Monad out. See Running StateT Computations.
  • @PathSource points an effect algebra to FreePath (#1008): a Path over a witness that @EffectAlgebra generates now draws a note at the witness. The algebra has a Functor and no Monad to pass to the Path's of and pure, so the note shows how to wrap its programs in a FreePath. See A witness another processor writes.
  • TrampolineUtils.traverseListStackSafe is stack-safe under every applicative (#1018): it combines the effects as a balanced tree, so a million-element traversal under IO no longer overflows the stack. It builds the result in linear time instead of copying the list at every element, and a Validated collecting its errors in a list is no longer quadratic in the failures. See Core Components.
  • A VStream releases its resources when it stops early or fails (#1024): closing reaches every finaliser upstream that the stream has started reading, through any operator, innermost first. takeWhile, zipWith, headOption, find, exists, forAll and a failing terminal operation close what they leave unread. So bracket(...).map(f).headOption() releases at once. VStream.closeAfterFailure closes a failed manual pull. See onFinalize: Lightweight Cleanup.
  • One Resource can serve overlapping uses (#1019): each use releases exactly what it acquired, however the Resource was composed. So a Resource built once with map or flatMap and used nested, or once per concurrent request, no longer releases one resource twice and leaks the other. See Using One Resource Many Times.
  • bracket, guarantee and withResource report a failing cleanup as try-with-resources does (#1053): when a use fails and its cleanup throws too, IOPath and VTaskPath report the use's exception with the cleanup's suppressed onto it. withResource, withResourceIO and Resource.fromAutoCloseable report an exception from close(), so a writer whose final flush fails no longer reports success. See The bracket Pattern.
  • VStreamReactive passes cancellation across the bridge (#1024): a toPublisher subscription closes the rest of its stream when it cancels or the stream fails, once it has requested elements. Closing a fromPublisher stream cancels its subscription, so take(n) stops the publisher. See Reactive Interop: Flow.Publisher Bridge.
  • A Scope can run again, be retried, or run on several threads (#1052): each run of the VTask from join() opens its own StructuredTaskScope with a new Joiner. A second run used to see the first run's results, and a retry kept failing with the first attempt's error. VResultPath.allSucceed, allSucceedAccumulating and firstSuccess are fixed too. See Running a Scope Again.

Spring

  • A streamed VStreamPath response closes its stream when it stops (#1024): a client disconnect, a timeout or a serialisation failure now runs the stream's finalisers. See VStreamPath: SSE Streaming on Virtual Threads.
  • An SSE stream from a declarative HTTP client closes when you stop early (#1024): headOption(), find(...) or take(n) on a stream from HkjClientExchange.vstream now closes the response. There is no need to drain it first. See Streaming with VStreamPath.

Testing

  • assertAffineLaws law-checks an affine that writes to an absent focus (#1023): Affines.some() and a Lens.andThen(Prism) affine now pass. On the absent target it checks that modify changes nothing, that set either changes nothing or writes a value that reads back, and set-set. Add assertSetNoOpWhenAbsent for an affine that must leave it alone. See When the focus is absent.

Build and tooling

  • MigrateDeprecationsTo0_5_0 drops the Monad that StateT no longer takes (#445): its new RemoveStateTMonadArgument recipe rewrites the constructor, create, stateT and mapT calls. Run it from hkj-openrewrite 0.5.0 while the project is on 0.4.11, since it matches the 0.4.x signatures. See 0.5.0 deprecation migration.
  • A generator extending the built-in Optional, Maybe, List, Set or Collection generator inherits no optic expression (#757): @GenerateFocus recognises those types by name and never asks a generator. So generateOpticExpression() and getRequiredImports() on them return the defaults, an empty string and an empty set. See Registering your own container type.
  • The state-t-mapt-arity check is retired (#445): every mapT now takes the function alone, so there is no missing argument to report. A disable= or severity: entry that names it has no effect. The kind-value-narrow message now names the right accessor: run() on ReaderT and WriterT, and runStateT(state) on StateT. See Compile-Time Checks.

Upgrading from 0.4.11

Before you upgrade

  • Run MigrateDeprecationsTo0_5_0 before you move to 0.5.0 (#445): take hkj-openrewrite 0.5.0 for the run, and keep the project on 0.4.11 until it finishes. Its StateT recipe matches the 0.4.x signatures, so it rewrites nothing once the build resolves 0.5.0. See 0.5.0 deprecation migration.

What a running program can notice

Optics

  • A map an optic writes iterates in the source's order (#1022): it came back in hash order, so printed output or a test of a map's iteration order can change. FocusPaths.mapValues over an empty map returns a new map.
  • A TreeMap keeps its order but not its type (#1022): forMapValuesCollecting(TreeMap::new) keeps both when the keys sort in their natural order. A TreeMap with its own comparator needs a collector that builds the new TreeMap with that comparator.
  • The function a predicate does not pick is no longer called (#1026): by modifyWhen and branch on a Traversal, and by modifyWhen and modifyBranch on a Lens. Lens.setIf no longer calls set on a failed predicate. So a logging, counting or throwing function sees only the values its predicate picks. Traversals.speculativeTraverseList is unchanged: it applies both functions to every element.
  • A read through an Optional or a Maybe reads a null focus as absent (#767): Fold.preview, TraversalPath.preview and toMaybePath, and FocusPath.toMaybePath used to throw NullPointerException. So did FocusPath.asAffine, headOption, IxedInstances.get and the list optics listAt, listHead and listLast, whose setters, and the list prisms' build, now write a null.
  • find passes over a null focus to the next match (#767): on Fold, TraversalPath, OpticOps and FoldExtensions, where a null match threw.
  • The element optics carry a null element through (#767): Setter.forList, and FocusPaths.listElements, arrayElements, listCons, listSnoc, listTail, listInit and mapValues, used to throw.
  • Plans.preflight walks a batched traversal to the end (#767): truncated is now false for one, since the walk's null stub values no longer halt it.
  • IxedInstances.contains counts an index holding a null as present (#767).
  • A traversal's Effect Path bridges leave a null focus out (#1017): toStreamPath, toVStreamPath and VStreamPath.fromEach used to stream it, and toListPath and toNonDetPath threw NullPointerException. TraversalPath.fold counts it as the monoid's empty value, where Monoids.string() appended "null". getAll still keeps every focus.
  • Sequenced lists are unmodifiable at every size (#1018): IndexedTraversals.sequenceList, ForTraversal.toList and ForIndexed.toIndexedList now return one, as Traversals.traverseList does. So do IndexedTraversals.forList on a non-empty list and Traversals.traverseArray on an empty array. Changing the result throws UnsupportedOperationException, so copy it into a new ArrayList first.
  • A @ViaConstructor lens with no parameterOrder sets through its constructor (#906): the order is read from the constructor's parameter names, where set used to throw UnsupportedOperationException.
  • A spec lens whose focus is wider than its getter's wrapper passes the value as it is (#906): with Number over an int getter, it used to be cast to int for withX(int). Where the wither, setter or constructor is also overloaded for a wider type, such as withX(Object), that overload is now the one called.
  • ForTraversal.toList and ForIndexed.toIndexedList honour the filters (#1018): they collect only the elements that pass filter and filterIndex, as modify and set already did. They used to return every focused element. See Collecting Results.
  • A query's predicate is not called after its answer (#1056): find, exists and all, on Fold, IndexedFold and TraversalPath, stop at the focus that settles them, so a logging or counting predicate sees fewer calls. A Fold of your own whose foldMap catches every exception still gives the same answer, but walks on to its end.
  • A read no longer runs a traversal's rebuild (#1056): a Traversal of your own whose rebuild logs or counts no longer runs it for Traversals.getAll, a TraversalPath's reads, IndexedTraversals.toIndexedList, getAll and length, or asIndexedFold().
  • OptionalTraverse.traverse rejects a function that returns null (#1056). For a present value, a null from the function used to give an empty Optional. It now throws NullPointerException, as the other Traverse instances do.
  • The list optics that returned an ArrayList now return an unmodifiable list (#1063): .each(), .at(i), .head() and .last() on a Focus path, ListTraversals, AtInstances.listAt and listAtWithPadding, and IxedInstances.listIx. Changing a returned list throws UnsupportedOperationException, so copy it first. With nothing at the index, .at(i) and listIx return your own list. See What each collection optic builds.
  • A Focus path over a field declared as ArrayList fails when .each(), .at(i), .head() or .last() writes (#1063): storing the rebuilt list, an unmodifiable List, back throws ClassCastException. .each() already failed on a one-element list. Declare the field as List, or use each(EachInstances.fromIterableCollecting(ArrayList::new)).
  • .each() over an empty list, and arrayEach().each() over an empty array, return a new empty one (#1063): not the source itself.

Effect Paths

  • StateT equality leaves out the Monad (#445): two StateT values wrapping the same function instance are equal, with equal hash codes, whichever Monad built them. toString prints only runStateTFn, so a test comparing the old text fails.
  • A list from PathOps or Par cannot be changed (#1017): the sequence and traverse methods, Par.all and Par.traverse handed back their working ArrayList. So changing the list inside an EitherPath changed what every later run() saw. Changing one now throws UnsupportedOperationException, so copy it into a new ArrayList first.
  • TrampolineUtils.traverseListStackSafe and sequenceStackSafe return an unmodifiable list (#1018): as Traversals.traverseList does. Changing it throws UnsupportedOperationException, so copy it into a new ArrayList first.
  • onFinalize runs its finaliser for each consumption of a VStream (#1018): a second consumption, or one after close(), used to skip it. It now also runs when the source fails as it is pulled. close() runs it for the latest consumption only, unless that consumption has run it already. See onFinalize: Lightweight Cleanup.
  • VStreamThrottle.throttle gives each consumption its own window (#1018): each consumption's first emission opens its first window. A later or concurrent consumption used to share the first one's window.
  • VStream.defer calls its supplier when the pulled VTask runs (#1024): not when pull() is called, and again on each run. generate, iterate and unfold call their functions then too. distinct, chunk and chunkWhile now give the same step each time a pulled VTask runs, and a distinct tail pulled again replays its elements.
  • VStreamPar.parEvalMap, parEvalMapUnordered and the VStream applicative's ap read their input when the pulled VTask runs (#1024): not when pull() is called, and afresh on each run.
  • Closing a pulled bracket stream releases its latest run (#1024): closing the head of a bracket after a pull releases the resource that pull acquired, where it used to release nothing.
  • A finaliser that used to be skipped now runs (#1024): when a VStream stops early, a terminal operation fails, or a function given to an operator such as map, filter or mapTask throws. A finaliser that throws then fails the operation that stopped, such as take or headOption. Closing runs the innermost finaliser first, as completing does.
  • VStreamPar.merge starts a producer for each run of its pulled VTask (#1024): not when pull() is called. Closing it stops that run's producer and closes each unfinished source. close() used to stop the producer when called; now it works when its VTask runs, as every stream's does, so run that VTask. See merge: Concurrent Multi-Source Consumption.
  • Cancelling a toPublisher subscription runs the stream's finalisers (#1024): once the subscriber has requested elements. It used to leave the stream open.
  • Resource.onFailure runs its action when the use fails (#1019): it used to do nothing. The action runs before the release, both when the use fails and when a step composed after it fails while the resource is held, such as map's function throwing. See onFailure Callback.
  • Resource.map releases the resource when its function throws (#1019): it used to leave the resource acquired.
  • A Resource rejects a null value (#1019): an acquire given to make or fromAutoCloseable that returns null, a null passed to pure, and a function given to map that returns null now fail with NullPointerException. A null used to be passed on to the use function. Hold an absent value as a Maybe instead. See Factory Methods.
  • A failing use keeps its own exception when cleanup fails too (#1019, #1053): in a Resource, and in IOPath.bracket, bracketIO, guarantee, guaranteeIO and VTaskPath.guarantee, the cleanup's exception is kept among the use's suppressed exceptions. When a release and a finaliser both throw, the release's exception is reported. The last exception thrown used to replace the others. See Exception Safety.
  • and(second, third) releases its first resource when two releases throw one exception (#1019): the same exception instance from both used to fail with IllegalArgumentException and leave the first resource acquired.
  • Cleanup after a failed use runs with the interrupt status cleared (#1019, #1053): a Resource's releases, finalisers and onFailure actions, and IOPath and VTaskPath cleanup, so a blocking close is not cut short. The status is restored afterwards. withResource also sets it when close() throws an InterruptedException.
  • An exception from close() fails withResource, withResourceIO and fromAutoCloseable (#1053): it used to be dropped. After a successful use, IOPath throws it unchecked, a SQLException as the cause of a RuntimeException, and the task from Resource.use fails. After a failed use, it is suppressed onto the use's. To ignore it, pass bracket or Resource.make a release that catches it.
  • withResource and withResourceIO reject a null resource (#1053): a resource supplier that returns null now fails with NullPointerException before the use runs. The use used to receive the null. Check for an absent resource before building the path.
  • A bracket whose use function throws releases the resource (#1024): before the failure reaches the caller. It used to leave the resource acquired.
  • Scope.firstComplete and ScopeJoiner.firstComplete() cancel the other subtasks once one completes (#1052): they used to wait for every subtask. Those still running are interrupted and those not yet started never start, so work a slower subtask does afterwards, such as writing a cache, no longer happens. Move work that must finish out of the race.
  • ScopeJoiner.joiner() returns a new Joiner on each call (#1052): code that opened a scope with one call and read result() from another now reads a Joiner no scope has used. That gives an empty result or an exception, so use the value the scope's join() returns.
  • A Scope's timeout cancels its subtasks (#1052): when it expires, those still running are interrupted, and the run fails with a TimeoutException once they have stopped. They used to keep running unobserved, so a subtask that ignores interrupts now delays the failure. Its subtasks now see the caller's ScopedValue bindings, which they used to find unbound.
  • An interrupt while a timed Scope waits fails the run (#1052): with an InterruptedException, as it does for an untimed Scope. A timed one used to ignore it and keep waiting.
  • Par and PathOps copy the list they are given when called (#1052): Par.race, all and traverse, and PathOps.sequenceVTask, traverseVTask, firstVTaskSuccess, parSequenceIO and raceIO. Changing the list afterwards no longer changes what a run does. A null task or path in a list, or in Scope.forkAll's, is rejected then, not when it runs.
  • Scope.named names the scope in a JSON thread dump (#1052): the name used to be dropped. named(null) now throws NullPointerException, where it was accepted.

Testing

  • assertAffineLaws no longer requires set to leave an absent target alone (#1023): a test that relied on it to catch an affine writing there now passes. Add AffineLaws.assertSetNoOpWhenAbsent(affine, absentSource, value) to keep that check.
