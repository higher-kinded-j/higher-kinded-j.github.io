Type Classes

"Civilization advances by extending the number of important operations which we can perform without thinking about them."

— Alfred North Whitehead, An Introduction to Mathematics (Chapter V)

This group adds operations you can perform on a container without thinking about which one it is: foldMap, traverse, orElse, select. Each needs the container to have an instance of the type class that declares it, and the hierarchy shows which class that is.

The Ship pages in the Chapter Contents teach the four type classes most code needs: Functor, Applicative, Monad and MonadError. The rest are here, with the For comprehensions that build on them. Read one when a task calls for it, such as folding a list into one value, validating every element with traverse, falling back with orElse, or mapping both sides of an Either. Until then you can skip the group.

Each arrow means extends, and each box lists the abstract methods its type class declares. A test in the examples module reads the boxes and arrows from hkj-api itself, so the diagram cannot show an extends the library does not have. An instance of a type class is an instance of every class it extends, so a Monad<F> can go wherever code asks for a Functor<F>.

MonadReader, MonadState and MonadWriter extend Monad too, and MTL Capabilities covers them. Bifunctor and Profunctor take a binary witness, which leaves two type arguments open, as Type Arity explains, and extend no other type class. Semigroup and Monoid take a plain type rather than a witness, and Monoid extends Semigroup.

Pages in this group

  1. Semigroup and Monoid: Combining two values of one type, and the empty value a combination starts from
  2. Foldable and Traverse: Reducing a container to one value, and running a step on every element to get one result holding them all

  6. MonadZero: A Monad with an empty value, which lets a For comprehension filter
  7. Choosing Abstraction Levels: Whether a task needs Applicative, Selective or Monad
  8. Bifunctor: Mapping either or both type arguments of a type such as Either or Tuple2
  9. Profunctor: Adapting what a function takes and what it returns
  10. Optics Integration: Lenses, prisms, isos and traversals as steps in a For comprehension
  11. MTL & ForState Bridge: MonadReader, MonadState and MonadWriter steps in a For comprehension, and the bridge to ForState
  12. ForState Comprehension: A comprehension that keeps its values in a named record rather than a tuple
