Stream: Java's Stream in Generic Code

Java's own type

java.util.stream.Stream makes each element only when something reads it, so a stream can run without end and still be read in part. Higher-Kinded-J does not replace it. It gives Stream an Effect Path, StreamPath, for application code, and a MonadZero instance, so that a method written once for any container accepts a stream too. A Java Stream can be read only once; a StreamPath can be run again.

The code on this page uses these imports:

import java.util.List;
import org.higherkindedj.hkt.effect.Path;
import org.higherkindedj.hkt.effect.StreamPath;

On a StreamPath

Path.streamIterate(seed, f) builds a fresh stream each time the path runs. So take limits an endless one, and the same invoices come back on every run:

    StreamPath<String> nextInvoices =
        Path.streamIterate(1001, n -> n + 1).take(3).map(n -> "INV-" + n);

    List<String> printed = nextInvoices.toList();
    List<String> printedAgain = nextInvoices.toList();
    boolean same = printed.equals(printedAgain);
    // true

Path.stream(stream) reads the whole stream when it is called, so that stream must be finite, and the path can then be run again. StreamPath.generate(supplier) and StreamPath.fromSupplier(supplier) build a fresh stream on each run, as streamIterate does. A StreamPath's zipWith gives every combination of two paths' elements, as a NonDetPath's does, and unlike StreamOps.zip. It reads both paths whole on each run, so take from an endless path first.

Invoice numbers without end

Code written once for any container takes a stream widened to a Kind<StreamKind.Witness, A>. The Foundations introduction's "Which level am I working at?" tip says when you need that. The stream keeps its laziness through the instance's map and flatMap. These are the extra imports, with LineItem from the order records the Optics chapter introduces:

import static org.higherkindedj.hkt.instances.Witnesses.stream;
import static org.higherkindedj.hkt.stream.StreamKindHelper.STREAM;

import java.util.stream.Stream;
import org.higherkindedj.example.book.optics.cast.LineItem;
import org.higherkindedj.hkt.Kind;
import org.higherkindedj.hkt.MonadZero;
import org.higherkindedj.hkt.Monoids;
import org.higherkindedj.hkt.instances.Instances;
import org.higherkindedj.hkt.stream.StreamKind;
import org.higherkindedj.hkt.stream.StreamOps;
import org.higherkindedj.hkt.stream.StreamTraverse;

Invoice numbers can come from a stream with no end:

  // Invoice numbers from 1001 on, without end: none is made until the stream is read
  static Kind<StreamKind.Witness, Integer> invoiceNumbers() {
    return STREAM.widen(Stream.iterate(1001, n -> n + 1));
  }

map adds the prefix to each number as it is read, and StreamOps.take stops after three:

    MonadZero<StreamKind.Witness> streams = Instances.monadZero(stream());

    Kind<StreamKind.Witness, String> invoices = streams.map(n -> "INV-" + n, invoiceNumbers());
    List<String> firstThree = StreamOps.toList(StreamOps.take(3, invoices));
    // [INV-1001, INV-1002, INV-1003]

Nothing is made until toList reads the stream, and then only three invoice numbers are. flatMap keeps the laziness too, so it reads an endless stream only as far as the consumer needs.

ap is the exception. Each function in its first stream needs every value in the second, so ap reads the whole second stream when it is called, and with an endless second stream it never returns.

A stream is read once

ORDER_LINES holds the lines of two orders:

  // The lines of two orders: a lamp and four bulbs, then a shade
  static final List<List<LineItem>> ORDER_LINES =
      List.of(
          List.of(
              new LineItem("LAMP", 1, new BigDecimal("40.00")),
              new LineItem("BULB", 4, new BigDecimal("2.50"))),
          List.of(new LineItem("SHADE", 1, new BigDecimal("15.00"))));

flatMap turns each order's lines into a stream of their SKUs, and joins those streams into one:

    Kind<StreamKind.Witness, List<LineItem>> orders = STREAM.widen(ORDER_LINES.stream());

    Kind<StreamKind.Witness, String> skus =
        streams.flatMap(lines -> STREAM.widen(lines.stream().map(LineItem::sku)), orders);
    List<String> picked = StreamOps.toList(skus);
    // [LAMP, BULB, SHADE]

A Java Stream can be used only once, and a Kind that holds one holds that one stream. Passing skus to any further operation, map as much as toList, throws IllegalStateException: stream has already been operated upon or closed. So build a fresh stream for each use, keep the elements in a List, or use a StreamPath.

Numbering and combining with StreamOps

StreamOps gives the common operations over a widened stream. zipWithIndex pairs each element with its position, counting from 0, which numbers a pick list:

    Kind<StreamKind.Witness, String> numbered =
        streams.map(
            pair -> (pair._1() + 1) + ". " + pair._2(),
            StreamOps.zipWithIndex(StreamOps.fromArray("LAMP", "BULB", "SHADE")));
    List<String> pickList = StreamOps.toList(numbered);
    // [1. LAMP, 2. BULB, 3. SHADE]

zip pairs two streams element by element, and concat puts one after another. The Methods table lists the rest.

Creating instances

STREAM.widen(stream) gives a Kind that holds a Stream, and StreamOps.fromArray(...), fromIterable(iterable), range(from, to) and rangeClosed(from, to) start one. The instance's of(value) gives a stream of one element, of(null) an empty stream, as Optional's and List's do, and zero() an empty stream. On a Path, Path.stream(stream), Path.streamFromList(list), Path.streamPure(value), Path.streamEmpty() and Path.streamIterate(seed, f) start a StreamPath.

Working with Kind

Generic code takes Stream through its MonadZero instance, from Instances.monadZero(stream()). Stream is a JDK type, so STREAM.widen wraps it in a small holder, and STREAM.narrow gives the stream back. The Alternative from Instances.alternative(stream()) puts one stream after another with orElse. StreamTraverse.INSTANCE is its Traverse, and so its Foldable, and reads the stream to fold or traverse it:

    Kind<StreamKind.Witness, Integer> quantities =
        STREAM.widen(ORDER_LINES.stream().flatMap(List::stream).map(LineItem::quantity));

    int items = StreamTraverse.INSTANCE.foldMap(Monoids.integerAddition(), q -> q, quantities);
    // 6

The two orders hold six items: a lamp, four bulbs and a shade.
