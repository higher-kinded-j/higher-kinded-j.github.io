Core Types

"I keep six honest serving-men: / (They taught me all I knew) / Their names are What and Where and When / And How and Why and Who."

— Rudyard Kipling, Just So Stories (The Elephant's Child)

Each family asks one of them of a value: what, if anything, it holds; why it failed; when it runs; where its settings come from; how many there are; or who runs it.

A core type is a container for a value, as Java's Optional is, and the library adds its own, such as Maybe, Either and IO. Application code reaches most of them through an Effect Path such as EitherPath, and generic code through their type class instances. The Foundations introduction says which you are writing.

Read a page when a task calls for its type, such as returning a typed error. Choosing a Type helps you pick one, and until then you can skip the group.

Pages in this group

  • Failure
    • Either: A value, or the first typed error
    • Validated: A value, or every error found, and Accumulating Assembly for records of validated fields
    • Try: A value, or a caught exception
    • EitherOrBoth: A value, an error, or a value with warnings
    • NonEmptyList: A list with at least one element, such as errors
  • Absence
    • Maybe: A value, or nothing, and never null
    • Optional: Java's Optional, with the same instances as Maybe
  • Deferred
    • IO: A side effect described now and run later
    • Lazy: A value worked out when first asked for, then kept
    • CompletableFuture: Java's asynchronous result, already running
  • Virtual threads
    • VTask: A deferred task, which runAsync, Par and Scope run on virtual threads, with Structured Concurrency and Resource Management
    • VStream: A stream that produces each element when pulled, with HKT and Type Classes, Parallel Operations, Performance, Resource-Safe Streaming and Advanced Features
  • Environment and state
    • Reader: A value worked out from settings
    • Context: Settings read from a Java ScopedValue
    • State: A step that reads a state and gives a new one
    • Writer: A value with a log beside it
  • Collections
    • List: Java's List, read as many possible results
    • Stream: Java's Stream, each element worked out when needed
  • Programs as data
    • Identity: A value and nothing else, for generic code with no effect
    • Trampoline: A recursion that runs without growing the stack
    • Free: A program written as data, for an interpreter to run
    • Free Applicative: Independent steps an interpreter can inspect before running them
    • EitherF: Two instruction sets joined, so one program can use both
    • Coyoneda: A Functor for any type, which joins its map calls into one
    • Const: A value of its first type and none of its second, for folds and getters

A type class, such as Functor or Traverse, names operations that work on any type with an instance of it, so a row tells you which generic code accepts that type. Every row lists the classes in the same order, so the differences show towards the end, and includes each class a listed one extends, as the hierarchy shows. MonadError<…> names the error its instance raises and recovers from: the type's own L or E, a Throwable, or Unit, the bare absence of Maybe and Optional. A test reads the table from the library's classes, so it lists exactly the instances of these type classes the library has. Semigroup and Monoid, which take a plain type rather than a container, are left out. Some instances take an argument: Validated's and EitherOrBoth's need a Semigroup to join two errors, and Writer's and Const's a Monoid to join two logs or two values.
