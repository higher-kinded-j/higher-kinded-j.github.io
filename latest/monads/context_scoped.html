Context: Reading Scoped Values

Read what the request bound, such as its trace id, without passing it through every call.

"This was no boat accident."

— Hooper, Jaws

Hooper will not accept the coroner's ruling: something did this, and he means to name it. A value read from a ThreadLocal was put there by something too, but the method's signature never says what. A method that returns a Context<String, A> says in its type that it reads a String the caller bound.

From ThreadLocal to ScopedValue

A request handler that keeps its trace id in a ThreadLocal must set it at the start and remember to clear it at the end. In between, any code it calls can set it to something else. JEP 506, which made ScopedValue final in Java 25, names three flaws of a ThreadLocal. The table sets each beside what a ScopedValue, bound for the length of one call, does instead:

ThreadLocalScopedValue
Changing the valueAny code that can reach it can set it, at any timeA nested call can bind a new value, and the outer value is back once that call returns
How long it lastsUntil something calls remove, or the thread endsUntil the call that bound it returns
Child threadsInheritableThreadLocal copies the values into each new thread, which costs every one storage of its ownThe threads a StructuredTaskScope forks share the bindings of the thread that opened it

Context<R, A> reads a ScopedValue<R> and gives an A. Like Reader, it needs a value that no method passes it. Unlike Reader, it finds that value in the bindings of the thread that runs it. Calling get() on the ScopedValue reads the value too. What a Context adds is that the read shows in its type, waits until the context runs, and composes with map, flatMap and recover.

Reading a trace id

The code on this page uses these imports, with Order from the order records the Optics chapter introduces:

import java.time.Duration;
import java.util.Locale;
import org.higherkindedj.example.book.optics.cast.Order;
import org.higherkindedj.hkt.context.Context;
import org.higherkindedj.hkt.context.RequestContext;
import org.higherkindedj.hkt.trymonad.Try;
import org.higherkindedj.hkt.vtask.Par;
import org.higherkindedj.hkt.vtask.VTask;

RequestContext.TRACE_ID is one of the keys the library defines, listed under Pre-built keys. It is a public static final ScopedValue<String>, made with ScopedValue.newInstance(), and you declare a key of your own the same way. ScopedValue is in java.lang, so it needs no import. ORDER is an order Ada has paid for, and an audit line about it reads the trace id:

  // The trace id comes from the binding, not from a parameter
  static Context<String, String> auditLine(Order order, String event) {
    return Context.asks(
        RequestContext.TRACE_ID,
        traceId -> "[%s] %s for %s".formatted(traceId, event, order.customer().name()));
  }

ScopedValue.where binds a value, and the context runs inside the call that follows:

    Context<String, String> paid = auditLine(ORDER, "payment taken");

    String line = ScopedValue.where(RequestContext.TRACE_ID, "req-7").call(paid::run);

line is "[req-7] payment taken for Ada". Building paid reads nothing, and the binding lasts only while call runs. Inside a nested where, the inner value hides the outer one until that call returns. A test binds whatever trace id it needs in the same way, with nothing to mock.

Bind around the run

toVTask() turns a context into a VTask: a task that runs only when something runs it, and that Par can fork. runSafe() runs a task and holds its outcome in a Try, a Success with the value or a Failure with the exception. A binding made while a task is built has ended before the task reads it:

  // The binding ends when call returns, before anything runs the task it built
  static VTask<String> boundWhileBuilding(Order order, String traceId) {
    return ScopedValue.where(RequestContext.TRACE_ID, traceId)
        .call(() -> auditLine(order, "payment taken").toVTask());
  }

  // The binding lasts while the task runs, so the task reads it
  static Try<String> boundWhileRunning(Order order, String traceId) {
    VTask<String> task = auditLine(order, "payment taken").toVTask();
    return ScopedValue.where(RequestContext.TRACE_ID, traceId).call(task::runSafe);
  }


    Try<String> tooEarly = boundWhileBuilding(ORDER, "req-7").runSafe();
    // Failure(java.util.NoSuchElementException: ScopedValue not bound)
    Try<String> whileRunning = boundWhileRunning(ORDER, "req-7");
    // Success([req-7] payment taken for Ada)

boundWhileBuilding returns a task built inside a binding that has since ended. Running it fails with NoSuchElementException, which ScopedValue.get throws for a key that is not bound. Inside another binding of TRACE_ID, it would read that one instead, and nothing would warn you. Put the where at the edge of the application, around the call that runs the task, as boundWhileRunning does.

Which threads see a binding

A binding belongs to the thread that runs the task, and to the threads a StructuredTaskScope forks from it. Par and Scope open their scope on the thread that runs the task, so the tasks they fork see its bindings. VTask.timeout runs its task on a new virtual thread, which does not. Par and Scope are built on Java 25's structured concurrency API, a preview feature, so code that names them needs --enable-preview, as On a VTaskPath explains.

    VTask<String> both =
        Par.map2(
            paid.toVTask(),
            auditLine(ORDER, "receipt sent").toVTask(),
            (first, second) -> first + "; " + second);
    VTask<String> timed = paid.toVTask().timeout(Duration.ofSeconds(30));

    Try<String> forked = ScopedValue.where(RequestContext.TRACE_ID, "req-7").call(both::runSafe);
    // Success([req-7] payment taken for Ada; [req-7] receipt sent for Ada)
    Try<String> ownThread =
        ScopedValue.where(RequestContext.TRACE_ID, "req-7").call(timed::runSafe);
    // Failure(java.util.NoSuchElementException: ScopedValue not bound)

To carry a value onto a thread that does not see it, read it on the thread that runs the task, then bind it again inside the task that timeout runs:

  // Read the trace id on the thread that runs the task, then bind it again inside the timed task,
  // which runs on a thread of its own. Only TRACE_ID is carried, so a step that reads another key
  // needs that key bound again too
  static VTask<String> timedWithTrace(Context<String, String> step, Duration limit) {
    return Context.ask(RequestContext.TRACE_ID)
        .toVTask()
        .flatMap(
            traceId ->
                VTask.of(() -> ScopedValue.where(RequestContext.TRACE_ID, traceId).call(step::run))
                    .timeout(limit));
  }


    VTask<String> carried = timedWithTrace(paid, Duration.ofSeconds(30));

    Try<String> timedAndTraced =
        ScopedValue.where(RequestContext.TRACE_ID, "req-7").call(carried::runSafe);
    // Success([req-7] payment taken for Ada)

timedWithTrace carries TRACE_ID alone. A step that reads another key needs that key read and bound again in the same way.

Several keys

R in Context<R, A> is the type of the value a chain reads, and every step of a chain reads the same type. TRACE_ID and CORRELATION_ID are both String keys, so they share a chain. A step that reads LOCALE, a Locale key, does not join a chain that reads String, and javac reports that the type variable "has incompatible equality constraints String,Locale":

import java.util.Locale;
import org.higherkindedj.hkt.context.Context;
import org.higherkindedj.hkt.context.RequestContext;

Context<String, String> both =
    Context.ask(RequestContext.TRACE_ID)
        .flatMap(traceId -> Context.asks(RequestContext.LOCALE, Locale::toLanguageTag));

Turn each read into a VTask with toVTask(), and chain those:

  // TRACE_ID holds a String and LOCALE a Locale, so the two reads meet in a VTask
  static VTask<String> confirmation(Order order) {
    return Context.ask(RequestContext.TRACE_ID)
        .toVTask()
        .flatMap(
            traceId ->
                Context.asks(RequestContext.LOCALE, Locale::toLanguageTag)
                    .toVTask()
                    .map(
                        language ->
                            "[%s] confirmation for %s in %s"
                                .formatted(traceId, order.customer().name(), language)));
  }

where calls chain, binding several keys for one call:

    VTask<String> confirm = confirmation(ORDER);

    Try<String> confirmed =
        ScopedValue.where(RequestContext.TRACE_ID, "req-7")
            .where(RequestContext.LOCALE, Locale.UK)
            .call(confirm::runSafe);
    // Success([req-7] confirmation for Ada in en-GB)

A key nobody bound

Reading a key that is not bound fails. run throws the NoSuchElementException, and runSafe() on the task from toVTask() holds it as a Failure. recover gives a default in its place:

    Try<String> nobodyBound = paid.toVTask().runSafe();
    // Failure(java.util.NoSuchElementException: ScopedValue not bound)
    String withDefault = Context.ask(RequestContext.TRACE_ID).recover(error -> "no trace").run();

withDefault is "no trace". toMaybe() runs the context at once and gives Nothing for any failure. A key bound to null fails too: ask fails with a NullPointerException when it runs. Read a key that may hold null with asks(key, Maybe::fromNullable), which gives Maybe's Nothing for it. RequestContext.getTraceIdOrDefault(fallback) reads the trace id directly, with a fallback.

Creating instances

Context.ask(key) reads a key, and Context.asks(key, f) reads it and applies f. Context.succeed(value) gives a value without reading anything. Context.fail(error) fails when it runs, though an Error is thrown at the call. It wraps a checked exception in a ContextException, so run declares none. recover and recoverWith are handed the original exception, while runSafe() on the task from toVTask() holds the ContextException. Context.map2 and map3 combine two or three contexts over one key type. A Context always gives a value, as Values, never null sets out. succeed(null) throws at the call, and a step that returns null fails the run, with a message naming the function, such as f must not return null.

Methods

Working with Kind

Generic code, written once for any container, takes Context through its Monad instance, from Instances.monad(context()). The key type is part of the witness, ContextKind.Witness<R>, so one instance serves contexts that read one key type. You widen a Context to pass it in, run the result with CONTEXT.runContext inside the binding, and CONTEXT.narrow(kind) gives the Context back. These are the extra imports:

import static org.higherkindedj.hkt.context.ContextKindHelper.CONTEXT;
import static org.higherkindedj.hkt.instances.Witnesses.context;

import org.higherkindedj.hkt.Kind;
import org.higherkindedj.hkt.Monad;
import org.higherkindedj.hkt.context.ContextKind;
import org.higherkindedj.hkt.instances.Instances;

    Monad<ContextKind.Witness<String>> traced = Instances.monad(context());

    Kind<ContextKind.Witness<String>, String> taken = CONTEXT.widen(paid);
    Kind<ContextKind.Witness<String>, String> sent =
        CONTEXT.widen(auditLine(ORDER, "receipt sent"));
    Kind<ContextKind.Witness<String>, String> together =
        traced.map2(taken, sent, (first, second) -> first + "; " + second);

    String ran =
        ScopedValue.where(RequestContext.TRACE_ID, "req-7")
            .call(() -> CONTEXT.runContext(together));

ran is "[req-7] payment taken for Ada; [req-7] receipt sent for Ada". The instance's map2 joins the two reads, and nothing reads the trace id until runContext runs them. The Monad helpers, such as peek and flatMapIfOrElse, work on it too, as Helpers built on flatMap and map shows. Widening allocates nothing: Context implements ContextKind itself, so widen checks for null and returns the same object.
